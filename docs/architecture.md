# Архитектура решения

## Логический поток

1. Источник заказов — CSV.
2. Источник товарных характеристик — REST API.
3. Airflow запускает последовательность задач.
4. Данные помещаются в staging.
5. ETL формирует размерности и факт в DWH.
6. ML-модуль выбирает признаки и обучает классификатор.
7. MLflow хранит параметры, метрики и артефакт модели.
8. Prediction-модуль формирует прогнозы.
9. Витрина `mart.v_order_dashboard` предназначена для BI.

## Модель данных

Использована звёздная схема:
- факт: `dwh.fact_order`;
- измерения: дата, клиент, товар, канал;
- аналитическая витрина: `mart.v_order_dashboard`;
- прогнозы: `mart.order_predictions`.

## Принцип least privilege

Для промышленного варианта рекомендуется выделить отдельные роли:
- `etl_writer` — запись staging и DWH;
- `ml_reader` — чтение DWH;
- `mart_writer` — запись прогнозов;
- `bi_reader` — только SELECT из mart.

В учебной демонстрации используется единый пользователь DWH для упрощения запуска.
